# 外部契约与平台验收缺口（S0-A）

本表只区分“当前客户端可证明的事实”和“仍需目标后端/平台确认的事项”。`docs/reference/http-api-legacy.md` 与 `statistics-api-snapshot.md` 均声明未记录可核对的后端生成提交，不能单独作为当前服务器已确认契约。本轮未调用真实接口、未写真实业务数据、未改服务端。

## EXT-STAT-01｜自定义统计区间与趋势请求

- **当前事实**：`StatsService.getExpenseTrends/getIncomeTrends` 只发送 `bookId/timeGranularity/timePoint`；分类、标签、交易对象等请求另发 `startDate/endDate`。`DashboardService` 的趋势方法虽接受可选 start/end，但不能证明统计页使用的 `StatsService` 已支持同一自定义窗口。历史快照把趋势定义为近 7 天、近 30 天、近 12 月、跨年，并同样只列 `timeGranularity/timePoint`。
- **缺口**：目标后端是否接受趋势 `startDate/endDate`，端点是否含边界、缺失日期如何补零、时区和账月开始日如何作用于趋势，均未由当前服务器版本确认。
- **影响**：DS-014、S8-A；与首页趋势范围相关的 S7-A 也不能只凭 UI 日期标签宣称一致。
- **本地可做**：冻结请求范围模型、为客户端参数组装和响应范围写合成 fixture 测试、让界面显示实际请求窗口。
- **不能声称**：自定义分析页所有图表已使用同一时间区间。
- **闭合步骤**：核对目标后端提交中的 `BillTrendsQuery`/控制器实现；用同一测试账本比较自定义跨月、跨年、账月起始日请求的原始参数与响应点；保存请求和响应证据。

## EXT-MONEY-01｜核对报告混币语义

- **当前事实**：`FinanceOrderReconciliation.currencyCodes` 是 `List<String>`；`OrderReconciliationPage` 直接取 `currencyCodes.first`，用于原支出、原收入、结算等多行金额。客户端模型没有证明所有金额已换算到同一币种。
- **缺口**：服务端是否保证单报告单币种、是否已完成汇率换算、列表顺序是否代表展示币种、混币时应分栏还是拒绝汇总，均未确认。
- **影响**：BO-060、S6-C；任何跨币种总计或百分比也不能外推到 S8-C。
- **本地可做**：用含 CNY/USD 的虚构响应写决定性测试，使首币种复用问题可复现；UI 可改为按服务端明确分组展示，但不能自行择汇率相加起来。
- **不能声称**：混币核对报告金额和币种已正确闭合。
- **闭合步骤**：取得目标后端 reconciliation DTO/计算实现和混币样例；确认每个金额字段对应币种及换算口径，再按真实契约验证汇总。

## EXT-ROLE-01｜协作角色枚举与默认授权

- **当前事实**：`GroupUsersService.getRoleTypes` 从 `/fortune/group/getRoleTypes` 动态读取并按数值排序；共享 `InviteMemberSheet` 通过 `initialRoleId` 选默认值。协作页取排序后的首项，分组详情优先取 2；`ManageRole` 另将 1/2/3 映射为 owner/actor/visitor。两个入口默认策略不同是客户端可复现事实，不等于已证明首项一定是所有者。
- **缺口**：目标环境实际角色值、描述、排序和权限含义，以及新角色出现时客户端能力降级规则。
- **影响**：MG-U01、S9-A；权限按钮可见性不等于服务端授权测试通过。
- **本地可做**：统一默认选择策略、展示角色后果、避免依赖排序推断权限，并用未知角色 fixture 验证安全降级。
- **不能声称**：默认邀请角色和服务端权限已全链路一致。
- **闭合步骤**：读取目标环境 `getRoleTypes` 真实响应与权限注解；用 owner/actor/visitor 测试账号分别验证可见动作和越权拒绝，不执行真实邀请也能先核响应和权限矩阵。

## EXT-REC-01｜周期时区与历史模板无损性

- **当前事实**：规则模型只有六段 `cronExpression` 字符串，没有时区字段；`CronBuilder` 生成 Spring 六段 cron。无法解析的旧 cron 在编辑器初始化时被改为默认每天 09:00。`billRequest` 虽可解析为 Map，但保存时由 `_buildBillRequest` 重建为有限字段；不支持的账单类型回退为支出，多个分类只取首项预填。历史 DTO 快照也未列 timeZone。
- **缺口**：服务端执行时区、`nextExecutionTime/lastExecutedTime` 的偏移约定、夏令时行为，以及现网历史 cron/模板字段的完整实样。
- **影响**：FB-REC-02、FB-REC-03、FB-REC-19、S14-A。
- **本地可做**：保留原始 cron 和原始模板 Map、对未知字段做无损 round-trip 测试、明确显示服务器返回的时间文本及其已知/未知时区；这些属于 S14 实现，不在 S0 修改。
- **不能声称**：旧规则已无损编辑，或下次执行时间已按用户时区准确表达。
- **闭合步骤**：核对调度器时区配置和历史规则样本；围绕月末、夏令时切换、多分类、垫付/报销和附加字段做读取—编辑—保存—再读取验证。真实自动执行写入必须另行授权。

## EXT-AUTH-01｜图形验证码替代通道

- **当前事实**：客户端仅发现 `/captchaImage`，响应为 `isCaptchaOn/captchaCodeKey/captchaCodeImg`，登录回传用户输入和 key；图片可刷新。当前客户端和历史快照均未发现语音验证码、短信、邮箱或其它非视觉验证接口。
- **缺口**：服务端是否已有未接入的替代通道，以及验证码允许字符、刷新后旧 key 失效规则。没有接口证据时不能编造“语音验证码”按钮。
- **影响**：FB-AUT-08、FB-AUT-09、S12-A；读屏可完成登录不能由图片加 Semantics 标签证明。
- **本地可做**：完善刷新忙碌、防旧内容提交、错误保留和非数字输入 fixture；若服务器没有替代通道，明确记录产品/平台阻断。
- **不能声称**：VoiceOver/TalkBack 用户已有等价登录路径。
- **闭合步骤**：由服务端确认可用替代验证契约及无障碍合规方案；在真实测试环境分别验证刷新、过期、错误、取消和非视觉通道，不绕过验证码。

## EXT-PROFILE-01｜性别清空

- **当前事实**：编辑页“－”把 `_sex` 设为 null；`ProfileService.updateProfile` 用 `if (sex != null) 'sex': sex` 构造请求，因此清空时字段被省略。历史 `UpdateProfileCommand.sex` 可为空，但“DTO 可空”不证明“省略字段会清空数据库”。
- **缺口**：服务器清空需要显式 JSON null、特殊枚举还是独立操作；省略字段究竟是保留还是置空。
- **影响**：FB-PRO-06、S13-A。
- **本地可做**：先让 UI 的未知/不设置/清空语义可区分，并为请求序列化写测试；实际清空策略必须服从服务器契约。
- **不能声称**：选择“－”后服务器资料已清空。
- **闭合步骤**：核对目标后端更新 SQL/DTO 的空值策略；用测试账号确认读取—清空—再读取结果，不能用虚构响应替代服务器结论。

## EXT-IO-01｜导入导出文件交付与平台验收

- **当前事实**：`IoService` 已声明 Excel 导出、模板下载和导入，能按 Content-Type 区分 JSON 结果与错误文件。Web 走浏览器下载、鸿蒙走系统文档保存；其它原生平台只写 `getTemporaryDirectory()` 并展示路径。导出当前仅发送 `bookId`，不继承账单页完整筛选。
- **缺口**：iOS/Android 的系统分享/保存/打开能力尚未形成统一交付闭环，目标设备未验证文件确实可取；服务器 Excel 字段、错误文件和计数也只由客户端模型及历史快照支持。
- **影响**：FB-IO-01 至 FB-IO-07、S15-A；其中 FB-IO-01 是明确平台缺口，其余条目仍需各自本地行为验证。
- **本地可做**：bytes/文件名/取消/失败结果模型、目标账本与文件确认、导入结果跳转和合成响应测试；S15-A 可采用项目已有平台能力做最小适配。
- **不能声称**：临时目录路径等于用户已收到文件，或 Web/鸿蒙实现已证明 iOS/Android 通过。
- **闭合步骤**：在 iOS 与 Android 分别执行导出、系统分享/保存、模板打开、错误 Excel 下载和用户取消；与测试服务器核对筛选范围、导入总数/成功/失败及生成记录。真实导入写账必须另获授权。

## 统一门槛

以上外部项在 `runtime/issue-checks/S0-A.json` 只建立关联，不被写成 VERIFIED_CLOSED。后续 owner 可以完成不依赖缺口的本地实现，但只要闭合需要上述契约或设备证据，阶段就必须保留 PARTIAL/BLOCKED_EXTERNAL，并在 handoff 中把 localGate、visualGate、externalGate 分开。
